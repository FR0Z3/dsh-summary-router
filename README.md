# dsh-summary-router

为 DeepSeek Harness（DSH）的**上下文压缩摘要**单独指定模型：换模型时那次压缩、自动压力压缩、上下文溢出恢复、手动 `/compact`，全部走你选定的路线。按会话、工作区、全局三级生效，并可配置失败回退链。

## 为什么需要它

DSH 的压缩摘要请求默认由**会话当前的路由模型**来写。换模型那一刻尤其容易出问题：

- 换到 B 时，DSH 先按 B 的上下文窗口判断要不要压缩，但摘要请求实际发给的是**旧模型 A**；
- A 的上游 429 或 30 秒不吐首包时，压缩失败，换模型被拒绝（`MODEL_SWITCH_COMPACTION_FAILED`），而待切换的选择仍留在队列里，于是每个 step 反复重试、反复失败；
- DSH 自带的 `summarizationProvider`/`summarizationModel` 字段能解决这个问题，但四个内置预设的 compaction 行都没有写 config，插件也没有 UI。

这个插件把「用哪个模型写摘要」做成可配置项，并支持多条回退路线。

## 工作方式

1. 拦截 `llm/stream`（所有模型调用必经的 waterfall），只接管 `purpose === 'compaction'` 且带 `sessionId` 的调用。
2. 按会话日志判断这次压缩属于哪条链：会话里「已提交的请求路由」与「待生效的模型选择」不同 → **换模型链**；否则 → **自动压缩链**。手动 `/compact` 有自己的事务标记（`compaction/start` 带命令 id），一律走自动压缩链，不会因为「刚选了新模型还没发消息」而误判。
3. 按顺序尝试链上的路线：先校验目标窗口装不装得下这段前缀（消息 + 工具定义 + 输出上限 + 安全余量 ≤ 窗口），装不下就跳过；每次尝试有独立的空闲超时。
4. 第一次成功的摘要原样交回 DSH；失败路线只记警告（附已产生的 usage），不消耗用户的步骤。
5. 全部失败时抛出明确错误（会出现在 DSH 自己的压缩失败信息里），并在配置冷却期内对该会话快速失败，避免每个 step 重复烧钱；**改动配置立即解除**。

## 它不做什么

它不决定**什么时候**压缩、不改任何阈值、也不做计费保护——那是压缩策略/计费插件的职责（例如 surcharge-guard）。它只决定摘要由哪个服务商、哪个模型来写，以及写失败时按什么顺序重试。

## 安装

在 DSH 的插件页安装 `github:FR0Z3/dsh-summary-router`（本地开发时可用指向本地目录的 `link:` 规格），启用后打开 **插件 → 摘要路由**。启用后刷新一次页面，客户端 bundle 才会加载。

## 使用

启用插件后，在 **插件 → 摘要路由** 里：

| 目标 | 操作 |
|---|---|
| 自动压缩用便宜模型 | 在「省钱链」里加一条路线（服务商 + 模型） |
| 换模型不再被压缩卡死 | 在「兜底链」里加一条稳定路线；保持「先尝试会话自己的模型」开启，原模型失败后自动换兜底 |
| 某个工作区单独配置 | 在「工作区覆盖」里加路径，填自己的路线；路线留空表示继承全局 |
| 只在这个会话用某模型 | 在会话里执行 `/compact-model provider/model [推理等级]` |
| 知道路由真的被触发 | 高级里打开「在会话里提示改路由」；每次摘要改由别的模型写，都会在会话里留一行提示 |
| 恢复默认 | `/compact-model off`，或把对应链清空 |

链为空 = 该触发不接管，行为与没装插件一致。

> **会话级覆盖没有 UI 入口**：DSH 的设置页是 profile 级的，拿不到「当前是哪个会话」，所以设置页只负责全局和工作区两层；单个会话的路线**只能用下面的命令**设置（它会写进该会话的日志，resume 后仍然有效）。

### 会话内命令

- `/compact-model`：自检。输出 `enabled`、命中的 `workspace`、`switch` / `pressure` 两条链各自的来源与顺序、本次实际会用的 `active` 触发、以及 `session route`（已提交）和 `pending route`（待切换）。
- `/compact-model provider/model [effort]`：只在当前会话固定一条路线（两条链都指向它，并跳过「先试原模型」）。写入会话日志（`plugin:` 记录，可回放、可审计）。
  - 固定前会预检：路由必须能解析（`resolveModelInfo`）；给了等级时还会用 `resolveCallConfig` 确认该模型真的支持这个等级；当前历史已经装不下该模型的窗口时，会直接提示「会被跳过」。
  - 多于一个等级参数会按用法错误返回，不会静默忽略。
- `/compact-model off`：清除会话级覆盖，回到全局/工作区链（大小写不敏感）。
- 写日志失败时，成功回复里会明确标注「未持久化」，不会假装保存成功。

### BetterSidebar

安装了 `dsh-better-sidebar` 时，插件会注册一个「摘要路由」标签页（开始页卡片、底部 + 菜单、DSH 右栏都能进）。没装时只在 DSH 设置页出现，不报错。

## 与 surcharge-guard 共存

两者可以同时启用。判据是那次摘要请求自己带的路由：

- **请求路由 ≠ 会话已提交路由** → 上游（如 surcharge-guard 的规则摘要模型、预设里的固定摘要设置）已经明确选了摘要模型。
  - **provider 与链路第一条相同**：先跑它选的模型（保留它自己的推理等级），失败后再按我们的链兜底；后续尝试各用各自配置的等级。
  - **provider 不同**：我们的链照旧接管。跨 provider 的一致性无法假设，而「换模型不再被压缩卡死」正是本插件要保证的事。
- **请求路由 = 会话已提交路由** → 没有上游选择，按两条链正常处理。

注意 `switchSessionFirst: true` 会让换模型链的第一条是**会话原路由**，因此 guard 指向别的 provider 时属于上面「不同 provider」的情形，会被我们的链覆盖。

## 限制

- **不是计费上限**：回退链的每一次尝试都会真实调用服务商并计费。链越长，最坏情况花费越多（失败尝试的 usage 会写进日志）。
- **摘要请求要把整段前缀重放给摘要模型**：目标模型的窗口必须装得下「会话前缀 + 工具定义 + 输出上限 + 安全余量」。便宜的小窗口模型只在历史不大时可用；装不下会被跳过并在日志里给出具体数字。
- 路线上的 `maxTokens` 只影响这次调用与窗口核算；DSH 的 `compaction/summary` 记录仍按压缩后端自己的上限写，插件会在自己的日志里注明本次实际上限。
- 插件**不能**修复上游网关自身的 30 秒首包限制；它做的是换一条能跑通的路线。
- 会话级覆盖写进会话日志后，DSH 的 `compaction/summary` 记录会显示实际执行的路线（插件会把成功路线的服务商/模型写回该次请求）。写日志失败时命令会明确提示「未持久化」。
- 「在会话里提示改路由」发出的那一行会作为上下文进入模型，计费与上下文都算它一份；默认关闭。
- 子代理会话有自己的 `sessionId`，默认同样适用；不想要时把 `purposes` 清空或对工作区单独配置。
- 只接管带 `purpose` 标记的辅助调用。第三方压缩后端如果用自己的调用方式且不带 `compaction` 标记，需要把它的 purpose 加进「匹配的辅助调用类别」。

## 开发

```sh
pnpm install
pnpm check
```

`pnpm check` 依次做语法检查、locale 双语一致性校验和单元测试。测试覆盖纯逻辑（作用域解析、链选择、窗口适配、熔断）、Host 拦截（换模型回退、跳过装不下的路线、全失败短路、命令）、设置页渲染与写入路径。

真机验证（用已安装的 DSH 跑真实的换模型压缩）：

```sh
ELECTRON_RUN_AS_NODE=1 "$DSH_NODE_EXECUTABLE" --test tests/installed-host.test.mjs
```

它用真实的 `BasicCompactionEngine` 与 `llm/stream` waterfall 验证：摘要请求 429 / 500 / 同步抛错时，兜底链接管、切换被放行、`compaction/summary` 记录真实路线；没有插件时同一个 429 会挡住切换。
